# Contributing

Thank you for contributing to Aqua Mnemosynth. The project values clarity, inspectability, and careful treatment of uncertainty.

## Before contributing

1. Read the [Project Overview](Overview.md) and [Core Concepts](Core-Concepts.md).
2. Check existing issues and pull requests.
3. Explain the problem before proposing a complex solution.
4. Keep claims, assumptions, and implementation behavior distinct.

## Documentation contributions

Documentation should:

- use direct language;
- define specialized terms;
- distinguish current behavior from future design;
- include examples where possible;
- state limitations and uncertainty;
- avoid unsupported claims.

## Code contributions

When implementation begins:

- keep modules focused;
- add tests for new behavior;
- preserve provenance and reasoning traces;
- validate external input;
- avoid silent fallback behavior;
- document public interfaces;
- update the wiki when architecture changes.

## Pull requests

A pull request should explain:

- the problem being solved;
- the approach taken;
- alternatives considered;
- tests performed;
- documentation changed;
- known limitations or follow-up work.

Small, focused pull requests are preferred because they are easier to review and revert.

## Review standards

Reviewers should look for correctness, clarity, security, privacy, explainability, and unintended consequences. Features that influence people or responsibility require especially careful review.

## Reporting problems

When reporting a bug or conceptual issue, include:

- a concise title;
- reproduction steps or a minimal example;
- expected behavior;
- actual behavior;
- relevant environment details;
- impact and possible workarounds.

Do not include private, identifying, or legally sensitive information in public issues.
